active milestone. This file preserves the detailed historical record.

## Explicitly Recoverable Alternatives and Consequences

Most early decisions did not record alternatives separately. The following
alternatives or consequences are recoverable from the approved planning record:

- **D-003–D-005 and D-074–D-077:** The Watershed evidence-first journey still
  displaces a broader multi-category or multi-hazard P0, but the evidence gate
  rejected the earlier score/rank/recommendation premise. Parks/heat remain P1 or
  evidence-gated context rather than competing core scope.
- **D-010, D-014, and D-078:** Using the $125 million Projects sub-envelope as
  historical/default context with binary full-request inclusion avoids treating
  other Watershed allocations as spare project funds, implying a partial-funding
  model, allowing the envelope to determine family membership, or calling an
  analyst-created Session Reference Plan historical.
- **D-012:** Historical outcome leakage is prohibited; the City benchmark cannot be
  used to tune or validate ClimateCapital analytical results and remains
  structurally isolated from evidence, family, membership, validation, and
  arithmetic.
- **D-015, D-035, and D-076:** The evidence gate found that P0 cannot support the
  contemplated rank, weights, score breakdown, or optimizer. Those outputs were
  removed rather than retained as empty or arbitrary artifacts.
- **D-017, D-032, D-040, and D-079:** Natural-language convenience remains bounded
  by structured review/confirmation and parity with the manual deterministic path,
  but weights and AI-originated recommendations were removed.
- **D-022–D-027:** Deadline protection takes precedence over optional breadth;
  missed gates cut scope rather than testing/recovery time.
- **D-028:** Compare was considered useful but not necessary for the core story and
  is therefore the first cut.
- **D-033:** A non-map path is mandatory because excluding projects for missing
  display geometry was rejected.
- **D-038 and D-041:** Persisted scenario management and workflow semantics were
  rejected for P0 in favor of one Session Reference Plan, one active What-If, and
  current-session review state.
- **D-044–D-056:** A dense all-in-one dashboard was rejected in favor of a minimal
  Explore workspace, dedicated Funding Plan, progressive disclosure, and focused
  methodology/help destinations.
- **D-057–D-059 and D-075–D-077:** Generic empty/error handling remains rejected.
  Filter matches, purpose-family membership, missing evidence, valid zero-project
  plans, over-budget attempts, and system failures have different meanings.
- **D-062:** “Controls closed” was chosen over the incorrect inference that all map
  overlays must be off by default; evidence still determines the visualization.
- **D-063:** Ambiguous “Historical context”/scenario labels were rejected in favor
  of Historical Envelope, Session Reference Plan, Current Confirmed Plan, and a
  separate Historical Benchmark.
- **D-064–D-066:** A monolithic progress file and a second progress tracker were
  rejected in favor of purpose-specific durable documents plus one canonical
  current-status file.
- **D-067–D-079:** Locking architecture or methodology against assumed project
  evidence was rejected. The completed evidence gate retains the City
  recommendation on a separate benchmark-only path, preserves the governed source
  and RNA provenance controls, and explicitly rejects a synthetic quantitative
  model. The resulting P0 uses one derived purpose-coherent family, transparent
  evidence roles/missingness, analyst membership, and deterministic budget
  arithmetic.
- **D-080–D-096:** Split frontend/API deployments, live source-dependent builds,
  runtime GIS/BigQuery, application/session/rate-limit databases, client-authority
  over plan results, benchmark coupling, AI Studio keys, paid throughput tiers,
  automatic Gemini calls, expansive observability, and fixture releases were
  rejected. The selected P0 uses one scale-to-zero Cloud Run container, a reviewed
  pinned release bundle, independently evaluated stateless plans, browser-session
  state, isolated benchmark, direct bounded OSM, required grounded explanation,
  keyless one-process Gemini controls, non-circular deployment identity, and
  post-schema data/application tracks that converge before release.
